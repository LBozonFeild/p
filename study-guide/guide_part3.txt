## Section 2 — Iteration and nested constructs

**Answer 1** (3 marks)
**Pseudocode:**
```
Total ← 0
FOR I ← 1 TO 10
    Total ← Total + I ^ 2
NEXT I
OUTPUT Total
```
**Python:**
```
total = 0
for i in range(1, 11):
    total = total + i ** 2
print(total)
```
**Why:** the till starts at 0; each lap adds the square of the lap number (1 + 4 + 9 + ... + 100 = 385). The loop counter is the number being squared — no literal 385 anywhere.
Mark points: initialising __Total__ (1); loop 1 to 10 accumulating the square of the counter (1); output of the calculated total (1). Accept __I * I__ / `i * i`.

**Answer 2** (2 marks)

**Python:** `for i in range(3, 8, 2): print(i)` — the end is 8 because `range` stops **before** its end value.
Mark points: correct output 3, 5, 7 (1); correct `range(3, 8, 2)` (1).

**Answer 3** (3 marks)
**Pseudocode:**
```
I ← 1
WHILE I <= 10 DO
    OUTPUT I * 2
    I ← I + 1
ENDWHILE
```
**Python:**
```

```
**Why:** a WHILE loop needs everything the FOR gave for free: the counter initialised before the loop (__I ← 1__), the test (__I <= 10__ — inclusive, or you lose the lap where I = 10), and the manual increment (the hamster-wheel rule).
Mark points: initialise the counter (1); correct inclusive condition (1); increment and correct WHILE structure (1).

Mark points: explaining the UNTIL polarity (1); corrected condition with both bounds and __AND__ (1); correct final code (1).

**Answer 27** (3 marks)

PROCEDURE PrintLine(Symbol : CHAR, Times : INTEGER)

**Answer 51** (2 marks)
**OR** lights for **one or both** inputs (1 OR 1 = 1) — either of two doors lets you in, even both. **XOR** lights only when the inputs **differ** (1 XOR 1 = 0) — one slice each, not both. They agree everywhere except the both-1 case.
Mark points: OR behaviour (1); XOR behaviour with the both-1 case (1).

**Answer 52** (3 marks)
__X = (A AND NOT B) OR (B AND NOT A)__ — the first term is "A is true and B is not", the second "B is true and A is not". This is the **XOR** gate, so __X = A XOR B__ (or __A EOR B__) is equally correct.
Mark points: correct expanded expression (2); correct parentheses (1). Full marks for the XOR form.

**Answer 53** (3 marks)
A **NOT** gate with input __B__. An **AND** gate whose two inputs are __A__ (direct line) and the output of the NOT gate. The AND gate's output is __X__.
Mark points: AND gate (1); NOT gate on B (1); correct connections (1).

**Model answer — Python (shortcuts used):**
```
def get_meals(day):
    """Ask for one day's sales, rejecting negative values."""
    while True:
        value = int(input(f"Meals sold on day {day}: "))
        if value >= 0:
            return value
        print("Invalid: the number must not be negative")

def find_highest(values):
    highest = values[0]
    for v in values:
        if v > highest:
            highest = v
    return highest

meals = []
for day in range(1, 11):
    meals.append(get_meals(day))

total = 0
for v in meals:
    total += v
average = total / 10
print(f"Total meals sold: {total}")
print(f"Average per day: {average}")

print(f"Highest day: {find_highest(meals)}")

above = 0
for v in meals:
    if v > average:
        above += 1
print(f"Days above average: {above}")
```

UNTIL (at least one attempt, stops when valid — the tea loop); the ten values are stored in the locker corridor before processing; the largest uses the seed-then-scan method of section 7.1; "above average" is a counting loop with the average as the test. Sanity-check with mental test data (e.g. 10, 10, ..., 10 → total 100, average 10, highest 10, days above average 0).
