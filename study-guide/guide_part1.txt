# How this guide works

This guide covers everything **after** the basics — you already know variables, input/output, operators and decisions, so those are skipped. What remains is the heart of Paper 2: iteration, strings, arrays, subroutines, files, standard algorithms, common errors, testing, flowcharts, Boolean logic, databases and the scenario question.

**Pseudocode and Python are treated as equals here.** Every concept is explained with a pseudocode example **and** a Python example, and every coding question has a model answer in **both** languages. Study both — the logic is identical, only the syntax differs.

Each section gives you explanations and worked examples, then practice questions with model answers and mark allocations. Try the questions **before** looking at the answers.

N: **The golden exam rule.** In the real Paper 2 exam, every coding answer must be written in **Cambridge pseudocode** — answers in Python (or any real language) score zero, **except** in the final 15-mark scenario question, where pseudocode **or** Python/Visual Basic/Java is allowed. Syntax is never marked: the **logic** is what earns marks. But operators must be precise: write __x > y__, never "x is greater than y".

In this guide, selection is built from **nested IF statements** throughout (in both languages), matching the syllabus requirement for nested selection and iteration. Where multi-way choice is needed, the Python examples nest IF statements inside ELSE blocks.

# 1. Iteration and nested constructs

## 1.1 The three loop types

Cambridge pseudocode has exactly three loop forms. Choosing the right one (and knowing when each runs **zero**, **one**, or **many** times) is a favourite exam target. Each is shown in both languages.

**FOR — count-controlled.** Use when you know in advance how many times to repeat.

**Pseudocode:**
```
FOR I ← 1 TO 10
    OUTPUT I
NEXT I
```
**Python:**
```
for i in range(1, 11):     # range stops BEFORE 11
    print(i)
```

- The counter is assigned every integer value from the start to the end value **inclusive** (Python's `range` is exclusive at the end — the classic translation trap).
- If start > end, the body never runs.
- A step size can be given, including negative steps:

**Pseudocode:**
```
FOR I ← 1 TO 9 STEP 2          // I takes 1, 3, 5, 7, 9
FOR Countdown ← 10 TO 1 STEP -1
```
**Python:**
```
for i in range(1, 10, 2):           # 1, 3, 5, 7, 9
for countdown in range(10, 0, -1):  # 10, 9, ..., 1
```

**WHILE — pre-condition.** Use when you repeat **while** something stays true and it might never be true at all. The test happens **before** each run, so the body can run zero times.

**Pseudocode:**
```
WHILE Password <> "Secret" DO
    INPUT Password
ENDWHILE
```
**Python:**
```
while password != "Secret":
    password = input("Password: ")
```

**REPEAT ... UNTIL — post-condition.** Use when the body must run **at least once**. The test happens **after** each run, and the loop **stops when the condition becomes TRUE** — the opposite of Python's `while`, a classic trap (see section 7).

**Pseudocode:**
```
REPEAT
    INPUT Password
UNTIL Password = "Secret"       // stops when TRUE
```
**Python:**
```
while True:
    password = input("Password: ")
    if password == "Secret":
        break                   # stops when TRUE
```

## 1.2 Totalling and counting

Two patterns you will use constantly — the same logic in both languages:

**Totalling (pseudocode):**
```
Total ← 0
FOR I ← 1 TO 5
    INPUT Value
    Total ← Total + Value
NEXT I
OUTPUT Total
```
**Totalling (Python):**
```
total = 0
for i in range(1, 6):
    value = int(input("Value: "))
    total = total + value
print(total)
```

**Counting (pseudocode):**
```
Count ← 0
FOR I ← 1 TO 5
    INPUT Value
    IF Value > 10
        THEN
            Count ← Count + 1
    ENDIF
NEXT I
```
**Counting (Python):**
```
count = 0
for i in range(1, 6):
    value = int(input("Value: "))
    if value > 10:
        count = count + 1
```

Always initialise the accumulator (__Total ← 0__ / `total = 0`) or counter **before** the loop.

## 1.3 Nested IF and nested loops

The syllabus requires **nested selection and iteration** (never more than **three levels** of nesting). In this guide multi-way choices are built by **nesting IF inside ELSE** — in both languages.

**Nested IF — grade bands.** One condition checked inside the other's ELSE branch:

**Pseudocode:**
```
IF Score >= 80
    THEN
        OUTPUT "Grade A"
    ELSE
        IF Score >= 60
            THEN
                OUTPUT "Grade B"
            ELSE
                OUTPUT "Grade C"
        ENDIF
ENDIF
```
**Python (nested if):**
```
if score >= 80:
    print("Grade A")
else:
    if score >= 60:
        print("Grade B")
    else:
        print("Grade C")
```

- Each nested IF has its **own** __ENDIF__ in pseudocode — count them carefully in error-finding questions.
- In Python the nested IF simply lives **inside the else block** and is indented one level further. Indentation is the structure.
- Three-way choice = one level of nesting; keep it at three levels or fewer.

**Nested loops — one total per row:**

**Pseudocode:**
```
FOR Row ← 1 TO 3
    RowTotal ← 0
    FOR Column ← 1 TO 4
        RowTotal ← RowTotal + Grid[Row, Column]
    NEXT Column
    OUTPUT "Total for row ", Row, " is ", RowTotal
NEXT Row
```
**Python:**
```
for row in range(1, 4):
    row_total = 0
    for column in range(1, 5):
        row_total = row_total + grid[row - 1][column - 1]
    print("Total for row", row, "is", row_total)
```
(If the Python grid is 0-based, subtract 1 from the indices — or build the grid 1-based style and keep the indices.)

## 1.4 Loops at a glance

T:
| Task | Pseudocode | Python |
| Count 1 to N | FOR I ← 1 TO N ... NEXT I | for i in range(1, N + 1): |
| Count with step S | FOR I ← A TO B STEP S ... NEXT I | for i in range(A, B + 1, S): |
| While condition is true | WHILE c DO ... ENDWHILE | while c: |
| Repeat at least once, until c is true | REPEAT ... UNTIL c | while True: ... if c: break |

## 1.5 Worked example — trace of a REPEAT loop

Trace tables track every variable and output at each step. For inputs 5, −3, 2, 0:

**Pseudocode:**
```
Total ← 0
Count ← 0
REPEAT
    INPUT Value
    IF Value > 0
        THEN
            Total ← Total + Value
            Count ← Count + 1
    ENDIF
UNTIL Value = 0
OUTPUT Total, Count
```
**Python (same program):**
```
total = 0
count = 0
while True:
    value = int(input("Value: "))
    if value > 0:
        total = total + value
        count = count + 1
    if value == 0:
        break
print(total, count)
```

T:
| Step | Value | Total | Count |
| before loop | - | 0 | 0 |
| 1 | 5 | 5 | 1 |
| 2 | -3 | 5 | 1 |
| 3 | 2 | 7 | 2 |
| 4 | 0 | 7 | 2 |

The loop stops after the input 0 (condition __Value = 0__ now TRUE). Final output: __7, 2__.

# 2. String handling

## 2.1 The four string operations

Strings are examined heavily because they combine naturally with loops and selection.

T:
| Operation | Meaning | Example | Result |
| LENGTH(s) | number of characters | LENGTH("Happy Days") | 10 |
| SUBSTRING(s, start, length) | substring of given length from position start (normally 1 = first character) | SUBSTRING("Happy Days", 1, 5) | "Happy" |
| UCASE(s) | all characters upper case | UCASE("Happy") | "HAPPY" |
| LCASE(s) | all characters lower case | LCASE('W') | 'w' |

The same operations in Python:

T:
| Pseudocode | Python | Note |
| LENGTH(s) | len(s) | same result |
| SUBSTRING(s, p, l) | s[p-1 : p-1+l] | Python slices are 0-based |
| UCASE(s) | s.upper() | |
| LCASE(s) | s.lower() | |

Strings join with __+__ in both languages: __FullName ← FirstName + " " + LastName__ / `full_name = first_name + " " + last_name`. Cambridge normally uses 1-based positions — questions will make this clear.

## 2.2 Processing strings character by character

The standard pattern is a loop from 1 to __LENGTH(s)__, extracting one character at a time — count the vowels in __S__:

**Pseudocode:**
```
Count ← 0
FOR I ← 1 TO LENGTH(S)
    Ch ← UCASE(SUBSTRING(S, I, 1))
    IF Ch = "A" OR Ch = "E" OR Ch = "I" OR Ch = "O" OR Ch = "U"
        THEN
            Count ← Count + 1
    ENDIF
NEXT I
OUTPUT Count
```
**Python:**
```
count = 0
for i in range(0, len(s)):
    ch = s[i].upper()
    if ch == "A" or ch == "E" or ch == "I" or ch == "O" or ch == "U":
        count = count + 1
print(count)
```

Reversing a string — loop downwards:

**Pseudocode:**
```
Reversed ← ""
FOR I ← LENGTH(S) TO 1 STEP -1
    Reversed ← Reversed + SUBSTRING(S, I, 1)
NEXT I
OUTPUT Reversed
```
**Python:**
```
reversed_text = ""
for i in range(len(s) - 1, -1, -1):
    reversed_text = reversed_text + s[i]
print(reversed_text)
# or simply: print(s[::-1])
```

Other common string tasks: counting occurrences of a character, checking a password against a rule, extracting parts of a formatted code.

# 3. Arrays

## 3.1 One-dimensional arrays

An array is a fixed-length block of elements of the **same** data type, accessed by index. Cambridge arrays usually start at 1; Python lists always start at 0.

**Pseudocode:**
```
DECLARE StudentNames : ARRAY[1:30] OF STRING
DECLARE Marks : ARRAY[1:30] OF INTEGER
FOR I ← 1 TO 30
    INPUT Marks[I]
NEXT I
OUTPUT Marks[5]
```
**Python:**
```
marks = [0] * 30              # 30 slots, indexes 0 to 29
for i in range(0, 30):
    marks[i] = int(input("Mark: "))
print(marks[4])               # the 5th mark
```
In Python a list can also grow: `marks.append(value)`.

Arrays are nearly always used **with loops** — to fill them, print them, search them, or sort them.

## 3.2 Two-dimensional arrays

**Pseudocode:**
```
DECLARE Grid : ARRAY[1:3, 1:4] OF INTEGER
Grid[2, 3] ← 7
OUTPUT Grid[2, 3]
```
**Python (list of lists):**
```
grid = [[0] * 4 for row in range(3)]   # 3 rows of 4
grid[1][2] = 7                          # row 2, column 3 in 1-based terms
print(grid[1][2])
```
Typical operations need **nested loops**: every row × every column.

Q:(3) Write an algorithm to declare an array capable of holding 20 integer exam marks, then fill it with values typed by the user. Write it in pseudocode **and** Python.

A: **Pseudocode:**

```
FOR I ← 1 TO 20
    INPUT Marks[I]
NEXT I
```

```
marks = []
```

# 4. Procedures, functions and modularity

## 4.1 Why split up code?

Topic 7 expects you to understand **decomposition** (breaking a problem into sub-systems) and Topic 8 expects **maintainable programs**: meaningful identifiers, comments (__//__ in pseudocode, __#__ in Python), and subroutines. A program built from small procedures and functions is easier to write, test, read and reuse.

## 4.2 Procedures (Python: functions with no return value)

A procedure performs a task and returns nothing. In pseudocode it is defined at the start of the code and called with __CALL__; in Python it is a `def` that is simply named:

**Pseudocode:**
```
PROCEDURE PrintLine(Symbol : CHAR, Times : INTEGER)
    DECLARE I : INTEGER
    DECLARE LineText : STRING
    LineText ← ""
    FOR I ← 1 TO Times
        LineText ← LineText + Symbol
    NEXT I
    OUTPUT LineText
ENDPROCEDURE

CALL PrintLine('*', 10)
```
**Python:**
```
def print_line(symbol, times):
    line_text = ""
    for i in range(1, times + 1):
        line_text = line_text + symbol
    print(line_text)

print_line('*', 10)
```
Parameters are typed in pseudocode (__Symbol : CHAR__); up to **three** parameters are examined. In Python, `print_line('*', 10)` is the "call" — there is no CALL keyword.

## 4.3 Functions (Python: functions with return)

A function performs a task and **returns one value**, so it is used inside expressions — never with __CALL__:

**Pseudocode:**
```
FUNCTION MaxOf(Value1 : INTEGER, Value2 : INTEGER) RETURNS INTEGER
    IF Value1 > Value2
        THEN
            RETURN Value1
        ELSE
            RETURN Value2
    ENDIF
ENDFUNCTION

OUTPUT "The winner is ", MaxOf(Score1, Score2)
```
**Python:**
```
def max_of(value1, value2):
    if value1 > value2:
        return value1
    else:
        return value2

print("The winner is", max_of(score1, score2))
```
The pseudocode definition states the return type (__RETURNS INTEGER__); in Python the returned value's type follows from what __RETURN__ sends back. A Python function without `return` comes back as `None` — a common bug (section 7).

## 4.4 Local and global variables

A variable declared **inside** a procedure/function is **local** — it exists only there, and shadows any global of the same name. Python behaves the same way: assigning to a name inside a function creates a **local**, unless you say `global` (best avoided — return values instead).

```

    FOR I ← 1 TO Times
        LineText ← LineText + Symbol
    NEXT I
    OUTPUT LineText

```

Mark points: correct header with both parameters (1); loop building the string (1); single output of the built line and a correct call (1).

```
    ENDIF

```

```
    return number % 2 == 0

for i in range(1, 11):
    value = int(input("Number: "))
    if is_even(value):
        count = count + 1
print(count)
```

```
    RETURN X * X
```

Q:(2) What does this program output? Explain why. Then show the Python equivalent and its output.

```
    Total ← 10
```

# 5. File handling

## 5.1 Why files?

Variables and arrays vanish when the program ends. A **file** on backing storage keeps data between program runs — for long-term storage, large data sets, or moving data between programs.

## 5.2 The four file operations

**Pseudocode:**
```
OPENFILE "Marks.txt" FOR READ      // or FOR WRITE
READFILE "Marks.txt", Mark
WRITEFILE "Marks.txt", Mark
CLOSEFILE "Marks.txt"
```
**Python:**
```
f = open("Marks.txt", "r")     # "r" = read  ("FOR READ")
mark = int(f.readline())       # READFILE one line
f.write(str(mark) + "\n")      # WRITEFILE one item/line
f.close()                      # CLOSEFILE
```
("w" = write, like __FOR WRITE__.)

- Open a file in **one mode at a time**.
- __FOR READ__ reads existing data; __FOR WRITE__ (Python __"w"__) creates a new file and **destroys anything the file already contained**.
- __READFILE__ / __WRITEFILE__ (or `readline()` / `write()`) move one item at a time into/out of a variable.
- Always __CLOSEFILE__ / `f.close()` when finished.

## 5.3 Typical pattern: process a file of values

**Pseudocode:**
```
OPENFILE "Scores.txt" FOR READ
Total ← 0
FOR I ← 1 TO 10
    READFILE "Scores.txt", Mark
    Total ← Total + Mark
NEXT I
CLOSEFILE "Scores.txt"
OUTPUT "Average is ", Total / 10
```
**Python:**
```
total = 0
f = open("Scores.txt", "r")
for i in range(10):
    mark = int(f.readline())
    total = total + mark
f.close()
print("Average is", total / 10)
```

N: The syllabus does not define an "end of file" test, so exam questions say how many items the file holds, or end the data with a sentinel value such as −1. Check the question for which pattern to use.

# 6. Standard algorithms, trace tables and debugging

## 6.1 The seven standard methods

The syllabus limits "standard methods of solution" to exactly these — you must be able to **write**, **trace** and **apply** each one in both languages:

- **Linear search** — find a value in an array
- **Bubble sort** — sort an array into order
- **Totalling** — add up values (section 1)
- **Counting** — count values matching a condition (section 1)
- **Finding the maximum** — largest value
- **Finding the minimum** — smallest value
- **Finding the average** — total ÷ count

Maximum (minimum works the same with __<__ / `<`):

**Pseudocode:**
```
Max ← A[1]
FOR I ← 2 TO 12
    IF A[I] > Max
        THEN
            Max ← A[I]
    ENDIF
NEXT I
```
**Python:**
```
max_value = a[0]
for i in range(1, 12):
    if a[i] > max_value:
        max_value = a[i]
```

## 6.2 Linear search

Walk through the array comparing each element to the search key; stop when found:

**Pseudocode:**
```
Found ← FALSE
Position ← 0
I ← 1
WHILE Found = FALSE AND I <= 4 DO
    IF A[I] = SearchKey
        THEN
            Found ← TRUE
            Position ← I
    ENDIF
    I ← I + 1
ENDWHILE
IF Found = TRUE
    THEN
        OUTPUT "Found at position ", Position
    ELSE
        OUTPUT "Not found"
ENDIF
```
**Python (positions 0-based):**
```
found = False
position = 0
i = 0
while found == False and i < 4:
    if a[i] == search_key:
        found = True
        position = i
    i = i + 1
if found == True:
    print("Found at position", position)
else:
    print("Not found")
```
Note the index bases: pseudocode position 1..4 with __<= 4__; Python index 0..3 with __< 4__.

## 6.3 Bubble sort

Repeatedly sweep through the array, swapping neighbouring pairs that are out of order. Each sweep "bubbles" the next largest value to its place:

**Pseudocode:**
```
FOR Outer ← 1 TO N - 1
    FOR Inner ← 1 TO N - Outer
        IF A[Inner] > A[Inner + 1]
            THEN
                Temp ← A[Inner]
                A[Inner] ← A[Inner + 1]
                A[Inner + 1] ← Temp
        ENDIF
    NEXT Inner
NEXT Outer
```
**Python:**
```
for outer in range(0, n - 1):
    for inner in range(0, n - 1 - outer):
        if a[inner] > a[inner + 1]:
            temp = a[inner]
            a[inner] = a[inner + 1]
            a[inner + 1] = temp
```

Worked trace sorting 5, 3, 4 (ascending):

T:
| Pass | Comparison | Swap? | Array after step |
| 1 | 5 vs 3 | yes | 3, 5, 4 |
| 1 | 5 vs 4 | yes | 3, 4, 5 |
| 2 | 3 vs 4 | no | 3, 4, 5 |
| 2 | 4 vs 5 | no | 3, 4, 5 |

Two "no swap" comparisons in a row mean the array is sorted.

## 6.4 Trace tables and dry-runs

A trace table documents a dry-run of an algorithm. Give **one column per variable** (plus one for outputs/prompts) and **one row per step** — usually one row per loop iteration. Exam tips:

- Write down the initial values row first.
- Show the row **after** each iteration's changes.
- If asked for outputs, add an OUTPUT column and write each output when it happens.
- Keep types consistent (don't put "TRUE" in a number column).
- A trace table works identically for the pseudocode and Python versions of a program — the logic is the same.

## 6.5 Debugging — quick recap

Section 7 lists the common syntax and logic errors in detail with corrections. For error-finding questions, remember the big five: missing increment (infinite loop), wrong comparison (off-by-one), uninitialised accumulator, array index out of range, wrong operator (__=__ where __←__ is needed, or words instead of symbols).

Q:(4) The array __A__ holds 7, 2, 9, 4 in positions 1 to 4 and __SearchKey__ is 9. Complete a trace table for the linear search below (columns __I__, __A[I]__, __Found__, __Position__) and state the output.
```
Found ← FALSE
Position ← 0
I ← 1
WHILE Found = FALSE AND I <= 4 DO
    IF A[I] = SearchKey
        THEN
            Found ← TRUE
            Position ← I
    ENDIF
    I ← I + 1
ENDWHILE
OUTPUT Position
```

A:
T:
| Iteration | I | A[I] | Found | Position |

Q:(5) Trace one complete bubble sort of the array __5, 3, 4__ (ascending order). Show the array after every comparison and swap, and say how you know the sort is finished.

A:
T:
| Pass | Comparison | Action | Array after step |
| 1 | 5 vs 3 | swap | 3, 5, 4 |
| 1 | 5 vs 4 | swap | 3, 4, 5 |
| 2 | 3 vs 4 | no swap | 3, 4, 5 |
| 2 | 4 vs 5 | no swap | 3, 4, 5 |
The sort is finished because pass 2 performs no swaps at all — every pair is already in order. Final array: __3, 4, 5__. The pseudocode of section 6.3 and its Python twin produce this identical trace.

Q:(5) Write an algorithm that inputs 12 integers and outputs the **largest** and the **smallest** of them, in pseudocode **and** Python.

A: **Pseudocode:**
```
INPUT Value
Largest ← Value
Smallest ← Value
FOR I ← 2 TO 12
    INPUT Value
    IF Value > Largest
        THEN
            Largest ← Value
    ENDIF
    IF Value < Smallest
        THEN
            Smallest ← Value
    ENDIF
NEXT I
OUTPUT "Largest is ", Largest
OUTPUT "Smallest is ", Smallest
```
**Python:**
```
value = int(input("Number: "))
largest = value
smallest = value
for i in range(2, 13):
    value = int(input("Number: "))
    if value > largest:
        largest = value
    if value < smallest:
        smallest = value
```

Q:(3) This bubble sort should sort __A[1]__ to __A[N]__, but it sometimes crashes. Identify the error and write the corrected inner loop line — then show the same bug in Python form.
```
FOR Outer ← 1 TO N - 1
    FOR Inner ← 1 TO N
        IF A[Inner] > A[Inner + 1]
            THEN
                Temp ← A[Inner]
                A[Inner] ← A[Inner + 1]
                A[Inner + 1] ← Temp
        ENDIF
    NEXT Inner
NEXT Outer
```

A: When __Inner = N__ the code reads __A[N + 1]__, which is **outside the array** (index out of range). The inner loop must stop one element early:
```
    FOR Inner ← 1 TO N - Outer
```
(__TO N - 1__ is also acceptable.) The same bug in Python:
```
for inner in range(0, n):          # WRONG - reads a[n] on the last pass
    if a[inner] > a[inner + 1]:    # IndexError when inner == n - 1 ... a[n]
```
Fixed: `for inner in range(0, n - 1 - outer):`.
Mark points: identifying the out-of-range read of __A[N + 1]__ (2); correcting the loop bound (1).

Q:(2) Explain why programmers use dry-runs and trace tables before running a program.

A: They verify the **logic** of an algorithm step by step without executing it — variable values and outputs can be checked at each stage, which reveals errors (wrong conditions, uninitialised variables, bad arithmetic) early, before coding or when no computer is available. The same dry-run works for pseudocode and Python, because the logic — not the syntax — is what is being checked.
Mark points: checking logic / finding errors before running (1); detail about tracking values at each step (1).

# 7. Common errors in pseudocode and Python

Most lost marks are not clever mistakes — they are the same dozen errors appearing again and again. Learn this section as a checklist.

## 7.1 Same idea, different syntax

T:
| Idea | Pseudocode | Python |
| assign | X ← X + 1 | x = x + 1 |
| compare equal | IF X = 5 | if x == 5: |
| not equal | IF X <> 5 | if x != 5: |
| integer division | DIV(10, 3) gives 3 | 10 // 3 gives 3 |
| remainder | MOD(10, 3) gives 1 | 10 % 3 gives 1 |
| power | X ^ 2 | x ** 2 |
| first element | A[1] (usually) | a[0] |
| loop 1 to N inclusive | FOR I ← 1 TO N | for i in range(1, N + 1): |
| repeat until true | REPEAT ... UNTIL c | while True: ... if c: break |

## 7.2 Pseudocode errors

**1. Assigning with = instead of ←**
```
Total = Total + 1          // WRONG: this compares
Total ← Total + 1          // RIGHT: this assigns
```

**2. Words instead of operator symbols**
```
IF X is greater than 5     // WRONG
IF X > 5                   // RIGHT
```

**3. Missing terminators.** Every construct closes: __ENDIF__, __ENDWHILE__, __NEXT I__, __ENDCASE__, __ENDPROCEDURE__, __ENDFUNCTION__. Count them in pairs.

**4. REPEAT ... UNTIL polarity.** The loop stops when the condition is **TRUE**:
```
REPEAT
    INPUT Password
UNTIL Password <> "Secret"     // WRONG: stops when password is NOT "Secret"
```
```
REPEAT
    INPUT Password
UNTIL Password = "Secret"      // RIGHT: stops when password IS "Secret"
```

**5. Uninitialised accumulator.** __Total ← Total + Value__ needs __Total ← 0__ before the loop, or the first total is garbage.

**6. Missing increment → infinite loop.** FOR/NEXT increments for you; in a WHILE loop you must write __I ← I + 1__ yourself.

**7. Array bounds.** For __ARRAY[1:30]__ the first element is __A[1]__ and the last is __A[30]__ — a loop from 0, or to 31, reads outside the array.

## 7.3 Python errors

**1. = is assignment, == is comparison**
```
if score = 100:            # WRONG: assigns (and is a syntax error here)
if score == 100:           # RIGHT
```

**2. Colons and indentation.** Every `def`, `if`, `else`, `while`, `for` line ends with __:__ . A nested IF sits **inside** the else block, indented further:
```
if score >= 80:                # WRONG shape for nested choice
print("A")
else:
print("B")                 # WRONG: not indented
```
```
if score >= 80:                # RIGHT
    print("A")
else:
    if score >= 60:
        print("B")
    else:
        print("C")
```

**3. range is exclusive at the end.** `range(1, N)` gives 1 to N−1. To include N: `range(1, N + 1)`.

**4. input() returns text.** `value = input("Age: ")` then `value + 1` fails. Use `value = int(input("Age: "))`.

**5. Text + number in print.** `print("Total: " + total)` is a TypeError. Use `print("Total:", total)` or `print("Total: " + str(total))`.

**6. Lists are 0-based.** `a[0]` is the first element and `a[len(a) - 1]` the last; habitually writing `a[i]` for i = 1..n reads one past the end (IndexError).

**7. while True without break.** A REPEAT translation must contain its `if condition: break` or it loops forever.

**8. A function without return.** Python returns `None` silently — forgetting `return` in a function that should return a value produces wrong results far down the line.

## 7.4 Logic errors that appear in both languages

- **Off-by-one conditions:** __<__ instead of __<=__ (or `<=` with a wrong end value) prints/counts one item too few — see section 1.
- **Wrong update direction:** in a smallest-value search, writing __IF Value > Smallest__ finds the biggest instead.
- **Totalling into the wrong variable:** __Count ← Count + Value__ (should be __Total ← Total + Value__) is silent — the program runs, the answer is wrong.
- **Wrong loop variable in a nested loop:** using __Row__ where __Column__ belongs (e.g. __Grid[Row, Row]__).
- **Case-sensitive comparison:** input "secret" fails against __= "Secret"__ — decide whether the question wants case-insensitive matching (__UCASE__ / `.upper()`).

Q:(4) The Python program below is meant to total the three scores 50, 70, 90 and print the total. It crashes. Identify the **two** errors and write the corrected program.
```
scores = [50, 70, 90]
total = 0
for i in range(1, 4):
    total = total + scores[i]
print("Total: " + total)
```

A: **Error 1 — 0-based index out of range:** `range(1, 4)` visits 1, 2, 3 but valid indexes are 0, 1, 2, so `scores[3]` raises IndexError. Fix: `range(0, 3)` (or `range(len(scores))`).
**Error 2 — text plus number:** `"Total: " + total` tries to join text to an int (TypeError). Fix: `print("Total:", total)`.
```
scores = [50, 70, 90]
total = 0
for i in range(0, 3):
    total = total + scores[i]
print("Total:", total)
```
Mark points: each error identified (2 — one per error); each fix shown (2).

Q:(3) This pseudocode is supposed to keep asking until the user enters a valid mark between 0 and 100 inclusive. It does the opposite. Identify the error and fix it.
```
REPEAT
    INPUT Mark
UNTIL Mark < 0 OR Mark > 100
```

A: __UNTIL__ stops when the condition is **TRUE**, so this loop stops when the mark is **invalid** — and keeps asking while it is valid. The condition must describe the state you want to stop on:
```
REPEAT
    INPUT Mark
UNTIL Mark >= 0 AND Mark <= 100
```
Mark points: explaining the UNTIL polarity (1); corrected condition with both bounds and __AND__ (1); correct final code (1). This is the pseudocode twin of the Python "while True / if: break" trap.

Q:(3) This pseudocode should output the sum 1 + 2 + 3 + 4 + 5 (= 15). Identify the **two** errors and write the corrected code.
```

    Total ← Total + I
NEXT I
OUTPUT Total
```

A: **Error 1 — uninitialised accumulator:** __Total__ is never set to 0, so the starting value is undefined.
**Error 2 — off-by-one bound:** __TO 4__ stops at 4; the question asks for 1 to 5.

```
Total ← 0
FOR I ← 1 TO 5
    Total ← Total + I

```
Mark points: spotting the missing initialisation (1); spotting the wrong upper bound (1); corrected code outputting 15 (1).
